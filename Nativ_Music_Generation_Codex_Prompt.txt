## 3. Product scope and native experience

### 3.1 Required first release

Add Music beside Chat and Images, using the existing workspace picker and layout. The user can enter a music description, optionally provide lyrics, choose vocals or instrumental, select a configured model, generate, see honest progress, listen, seek, save/export, and revisit earlier results.

Default flow:
- Select a local ACE-Step 1.5 Turbo profile, after installation and hardware qualification.
- Start with one 30-second draft and one output per request. Longer durations are available only within the selected provider's tested limits.
- Do not download weights or load a large model just because Music became visible. Present an integrated setup/download flow with real sizes, free-space checks, cancellation, and retry.
- An instrumental toggle removes irrelevant lyric controls. Manual lyrics are preserved exactly unless the user explicitly requests a rewrite.
- When a selected vocal provider requires lyrics, mark that field required and validate it before submission. Do not silently invent/rewrite lyrics or make a separate paid language-model call; any lyric-writing aid is an explicit action using a deliberately selected supported text model.
- Keep advanced controls collapsed: duration where supported, seed, BPM/key/time signature where supported, sampling profile, and model-specific options. Label generative hints as hints rather than exact guarantees.
- Defaults are per provider/profile. Switching from ACE-Step to a provider without seed or exact-duration support must update the controls and request accordingly; do not carry hidden unsupported parameters into the next submission.
- Persist successful songs and their generation metadata locally, as Images persists outputs. Default to retaining originals until the user deletes them. Do not silently auto-upload, auto-publish, or add files to external music services.
- No autoplay on job completion, reopening a session, or receiving an API-created song. Playback is a deliberate user action.

A result card contains a useful title, provider/model and Local/Remote label, actual audio duration, waveform, play/pause, scrubber, elapsed/remaining time, volume, lyrics if available, generation details, Regenerate as a new job, and Export. Keep a compact shared player while navigating within Nativ. One app-scoped playback coordinator prevents overlapping songs across windows.

Generate new music through a native generate_music chat tool as well. Follow the existing image-tool model-picker and approval/access-level flow. The chat tool submits the same public job schema and returns a stable job reference immediately; its result card observes completion. Do not hold the chat inference lease while waiting for a music worker that needs that lease. Do not let the model choose arbitrary endpoints, credentials, output paths, or a paid fallback. Expose the tool only when the feature and a compatible configured provider are available. Keep live-translation interpreter sessions tool-free.

### 3.2 Visual and interaction quality

Use Nativ's actual fonts, colors, separators, spacing, composer shape, popovers, model menu, empty states, and native sheets. The inspected Images view uses an 860-point transcript maximum, 680-point composer maximum, and 32-point horizontal padding; treat these as existing design references, not constants to duplicate if upstream has changed.

Show distinct states: model setup required, downloading, queued, waiting for Resume after restart, preparing model, generating, writing audio, completed, cancellation requested, cancelled, interrupted, uncertain remote outcome, and actionable failure. Display a percentage only when the adapter provides a meaningful bounded measure. Otherwise show stage, elapsed time, queue position, and an indeterminate animation. An invented percentage must never imply a completion guarantee.

Use a quiet animated generation indicator and a waveform derived from real decoded audio once available. Do not animate a fictional signal as if audio were already playing. When the provider genuinely supports usable preview audio, label it Preview and commit the final asset separately. Cache downsampled waveform peaks off the main thread; animate only visible active components. Respect Reduce Motion, Reduce Transparency, VoiceOver, keyboard navigation, sufficient contrast, and narrow window layouts. Avoid a mandatory notch overlay; this is a workspace feature.

Switching workspace, minimizing, or closing one window must not cancel a submitted server job. Reopening attaches to the same job. Explain that generation continues while the local server/app remains running; do not imply an independent operating-system daemon exists. Quitting or stopping the server follows the explicit shutdown/recovery policy below.

### 3.3 Model selection must tell the truth

Separate these concepts in the interface and API:
- Model family/checkpoint.
- Runtime and exact revision.
- Deployment: on this Mac, my configured GPU server, or a hosted paid provider.
- Availability: ready, download required, configuration required, unsupported hardware, experimental, or disabled.
- Supported operations and actual constraints.

Never label a remote MiniMax server as local Mac inference. Never infer music capability from a MiniMax logo, a TTS/STT capability, or a generic audio tag. A provider unavailable to the account must not be silently replaced by another provider.

### 3.4 Deliberate second-stage scope

Keep seams for reference-audio generation, covers, repaint/inpaint, variations, continuation, stems, and LoRA. Only expose an operation after the exact checkpoint/runtime supports it and it has an end-to-end implementation and test. ACE-Step Turbo does not inherit all Base-model editing capabilities. Do not ship inactive editing controls as completed functionality.

The required initial feature is text/lyrics-to-music plus the common library/API experience. Cover/edit workflows can follow as separate, working increments. MIDI generation, a full DAW, voice cloning, dataset training, and realtime DJ performance are outside this initial build.

### 5.2 Stable provider contract

Use a typed internal protocol equivalent to:

MusicProvider.capabilities() -> ProviderCapabilities
MusicProvider.prepare(deployment, cancellation) -> PreparedProvider
MusicProvider.run(job, emit_event, cancellation) -> ProviderResult
MusicProvider.cancel(handle) -> CancellationResult
MusicProvider.shutdown() -> None

PreparedProvider includes runtime/checkpoint identity and actual device/output formats. ProviderResult contains validated candidate media files or bounded download handles, measured metadata, effective parameters, and provider request identifiers; it does not publish a job as successful itself.

The service assigns a unique job_id and attempt_id. Events and results include both. Only the active attempt may change a job. A late event after cancellation/restart must not update the UI or overwrite a newer asset. Persist provider request identifiers as soon as they exist so restart recovery can query known operations safely.

Before any provider submission, durably record the attempt's dispatch intent; reserve the idempotency key and job atomically before that. A remote dispatch intent left unresolved after a crash becomes submission_unknown, even if the crash may have occurred before the network send. Never replay that POST unless the provider documents idempotency and the tested adapter safely reuses that same provider identity. Query a known operation when possible. Test crashes immediately before send, after provider acceptance and before response persistence. Exactly-once remote execution cannot be invented around a provider that has no such contract.

Snapshot the accepted deployment/profile revision and normalized requested configuration. Revalidate enablement, credentials and compatible profile identity immediately before dispatch or Resume. Disabling a provider or editing its URL/model must not silently retarget an accepted job. Surface an actionable configuration mismatch; a changed request is a deliberately new job.

Capabilities must include deployment type, vocals/instrumental/lyrics, supported operations, duration control semantics and bounds, seed support, formats/rates/channels, reference input support, progress granularity, preview audio support, cancellation semantics, and qualification status. Use explicit unsupported/unknown values. Server validation and UI controls use the same capabilities.

Distinguish hard duration bounds, an output ceiling, and a prompt-only duration hint. Unsupported controls produce a field-specific validation error. Do not silently ignore seed, duration, instrumental, or reference inputs. Preserve requested and effective parameters separately; return actual duration measured from the result.

### 5.3 Job lifecycle and limits

Use explicit states: queued, recovery_hold, preparing, running, finalizing, succeeded, cancel_requested, cancelled, interrupted, failed, submission_unknown. Define legal transitions and test them. Progress is optional and stage-scoped. Do not average unrelated provider progress into fabricated global accuracy.

Initial bounded defaults, configurable through documented application settings:
- One active local heavyweight music generation.
- One active hosted/remote generation and at most eight queued music jobs in total.
- One output per request; Regenerate creates a new job with its own key/seed policy.
- Music submission JSON at most 128 KiB; validate provider-specific text limits before queueing.
- At most 1 GiB per imported output, with both header checks and streaming byte limits.
- Keep only bounded event history per job, for example the latest 1,000 progress/state events. Coalesce high-frequency progress; never let logs or SSE queues grow with every model step forever.

Reject overload with a structured retryable error and Retry-After where meaningful. Queued jobs must not pin large model memory. Use stage-aware watchdogs and a documented execution ceiling from the qualified profile; a valid long generation must not inherit a short generic HTTP timeout.

Cancelling a queued job prevents provider submission. Cancelling a local job first requests cooperative cancellation; after a short bounded grace period terminate only Nativ's owned dedicated worker/process group and restart it cleanly for the next job. A shared provider process handling other owners' work must never be killed. Do not claim cooperative mid-step pause if the runtime cannot do it.

For a remote service without a documented cancel operation, cancellation stops local observation/import and marks remote cancellation as unconfirmed; the provider may continue and bill. Expose that fact in the API result and UI. A network failure after submission is not proof of failure. Persist submission_unknown and do not blindly submit again. A confirmed completed job remains completed when Cancel arrives too late.

Track local observation state, provider execution outcome and remote capacity reservation separately. submission_unknown and cancellation-unconfirmed attempts retain their remote reservation until the provider is known terminal or the user deliberately releases it after acknowledging possible ongoing execution/billing. Background reconciliation may query an existing operation but must never create another generation. An explicit release operation affects capacity only: it does not prove cancellation, change the original request identity or make replay safe. Document that the default limit covers Nativ-reserved operations; a user override may allow overlap with an unresolved provider job.

On clean server shutdown, stop admission, persist queue/state, cancel owned workers, and close streams. On restart, preserve existing terminal states and honor persisted cancellation requests first. Only eligible nonterminal local or remote jobs with no durable dispatch intent enter recovery_hold and require explicit Resume using the same job and idempotency identity. An unresolved remote dispatch intent becomes submission_unknown rather than recovery_hold. Mark interrupted in-flight local work interrupted; Regenerate creates a new job and never pretends to resume model state. Reconcile known remote operations without another paid POST. Unknown remote outcomes require a deliberate new request to try again, with the reservation and possible-charge explanation. Files remain intact. Quitting must disclose pending work and offer the existing stop/quit choices without creating an unrequested system daemon.

Require Idempotency-Key for all generation submissions, including native and chat clients; a missing key is HTTP 400 with a field-specific error. Return HTTP 202 quickly with store_id, job_id, state, created_at, status_url, events_url, and normalized accepted parameters. A duplicate request returns the original job, including submission_unknown, without another provider call. Store idempotency records for the entire job lifetime and retain tombstones for at least seven days after any future job-record purge. Publish the actual retention window; do not promise duplicate suppression after its expiry. The same key with a different canonical request is HTTP 409. Normalize JSON key ordering and omitted/default fields consistently before computing the request identity.

Remote examples must explicitly name a configured remote model and set allow_remote=true. Configuration must separately enable that provider and store its credential. No automatic local-to-cloud or one-provider-to-another fallback. A client with the Nativ server key can use enabled capabilities; explain this when enabling paid providers. Do not accept a new endpoint URL or credential inside an ordinary generation request.

Status responses contain store_id, requested/effective configuration, accepted profile revision, stage/progress, timestamps, cancellation capability, provider identity, local observation state, provider outcome, remote reservation state, safe error fields, and asset references only when available. Errors use a stable structure such as error.code, message, field, retryable, and job_id where applicable. Never leak secrets, raw upstream traces, filesystem paths, or temporary signed URLs.

Resume is legal only for a never-dispatched recovery_hold job and retains its identity after revalidation. Repeated Resume/Cancel operations are idempotent. release-remote-reservation requires an explicit acknowledge_possible_execution_and_charges=true body and is only applicable to unresolved remote work. It must never submit a new attempt. Explain these semantics in Developer examples and the native recovery UI.

SSE is a job event stream, not automatically an audio stream. Support event IDs and Last-Event-ID, heartbeat, bounded buffering, reconnect, and a current snapshot when a requested cursor is older than retained events. Disconnecting an SSE/GET client does not cancel the job. Provide polling as a fully supported fallback. A terminal event is emitted only after the durable state/asset commit.

All music routes, including content downloads and event streams, use the server's actual bearer authorization. Do not copy a fail-open optional call to a private auth helper. If the running server cannot enforce the required dependency, fail music startup closed with a useful diagnostic, while preserving unrelated services. Keep loopback as default, reject unauthorized cross-origin browser requests, and do not enable wildcard credentialed CORS. Preserve existing server authentication configuration and do not silently rotate a user key.

Content downloads provide correct Content-Type, Content-Length, ETag and byte-range behavior (206/416), with a safe Content-Disposition filename. Authentication is in headers, never query strings. Resolve opaque asset IDs into managed paths; reject traversal, symlinks escaping the store, and requests to arbitrary provider paths. Export/download failures must be retryable without regenerating music.

Delete moves an unused managed asset to recoverable trash under the same lifecycle as the UI. Return HTTP 409 with usages if live chat/session/reference reservations remain. Explicit reference deletion unlinks only the named usage; it does not delete another client's chat or silently cascade through every usage. A generation's historical provenance record is not itself a perpetual live usage, and it remains meaningful when an asset is trashed. Restore retains the same asset ID. A cancelled job is not a request to delete earlier completed songs. Keep reads/listing available for old results when a provider is disabled or its key expires.

## 7. Persistence, artifacts, playback, and credentials

### 7.1 Canonical library

Use the fork's configured application-support root, never a new hardcoded upstream Nativ directory. A suitable layout is Music/jobs.sqlite, Music/assets/<asset_id>/original.<extension>, Music/assets/<asset_id>/manifest.json, Music/assets/<asset_id>/waveform.json, and Music/Trash/. Keep runtime caches and temporary partial files separate from the user's completed songs.

The service owns durable sessions, jobs, events, idempotency, and asset metadata. Swift may keep a rebuildable presentation cache but must not independently rewrite authoritative job state. Each job belongs to a stable music session. If an API submit omits session_id, create one atomically. Expose GET/POST /v1/music/sessions and PATCH /v1/music/sessions/{session_id} for paginated listing, creation, renaming and hiding sessions. Do not delete output files just because a session is hidden from the sidebar. Session deletion/unlink semantics must use the same asset-reference rules as the app's Trash flow.

Python is the only writer of canonical music files, active asset references and trash state. Swift Artifacts is a rebuildable projection keyed by store_id and asset_id; it never independently moves or deletes a music original. Implement the authenticated reference/usage/trash/restore routes listed above for both UI and API. Create a session usage transactionally with the successful output. A user deleting a result deliberately unlinks that usage first; other chat/API usages remain protected. Never treat merely reading/downloading a file as a durable reference.

Use stable reference_id values and idempotent attach/detach operations. For Swift-owned chat attachments, persist a durable local outbox and reserve the reference in the music service before committing a new chat attachment; finalize the reservation after the chat write. If disconnected, retain a pending action instead of claiming that the canonical mutation succeeded. Reconcile pending operations on reconnect/restart; an uncertain reference or orphan reservation blocks destructive deletion until reconciled. Test crashes before/after reference reservation, chat save and completion acknowledgment. A missing client must not cause an unverified cascade delete. Keep reference ownership and repair rules explicit rather than assuming a distributed transaction.

Nativ's existing MediaAssetStore is defined in ChatSessionStore.swift and has an independent owners.json garbage-collection mechanism. Do not let it independently own/delete the same canonical Music file. Music-backed chat/artifact entries must store stable service asset references and use a clear bridge; any downloaded display/export cache is a disposable cache, not a second original. Document the ownership boundary and test that unrelated MediaAssetStore cleanup cannot remove a song still referenced by a job or API client.

Write provider output to a private .partial file, validate it, compute its digest and decoded metadata, then atomically publish it. Commit the database asset reference and terminal job state in a recoverable order. Add startup reconciliation for a crash between file rename and database commit. Disk-full, corrupt audio, or a failed thumbnail/waveform must not leave a job claiming a playable asset that does not exist. A waveform-cache failure should not destroy a valid original.

Retain original audio bytes and format. An exported WAV transcoded from MP3 is not a lossless original. Report that provenance honestly; do not upsample and call it improved quality. Record sample rate, channels, codec, duration, byte size, SHA-256, model/checkpoint/runtime revision, effective seed if returned, prompt/lyrics, created time, and optional provider request ID. Do not save a secret, signed download URL, or absolute provider path in a manifest.

Support WAV and MP3 playback/export first; add FLAC only where the actual codec/export pipeline supports it. Distinguish provider-native output formats from Nativ's explicit export conversion. Decode file metadata from bytes rather than trusting a JSON extension. Avoid reading a large complete file into multiple copies of Data just to play it or draw a waveform. Use AVFoundation's file-based playback and background peak extraction. Use the existing audio playback/resource coordinator when appropriate, without mixing music into the voice-note history.

Add ArtifactKind.audio and ArtifactUsage.Workspace.musicGeneration, or the precise compatible equivalents found during reconnaissance. Update every affected exhaustive switch, filter, icon, search/index schema, recovery/trash operation, and deep link. Old JSON, chat sessions, image history, and indexes must still decode. New optional metadata must not become required for old artifacts. Music assets created through the API must appear in the same Music session/library and in Artifacts without duplicate copies. A chat card points to the same asset and can open its Music session.

Do not parse generated lyrics as executable commands, write paths from a model output, send generated music through automatic ASR, or auto-read a lyrics block using the chat TTS feature. All use/export/copy actions are explicit.

## 8. Runtime packaging, compute coordination, and coexistence

### 8.1 Managed runtime isolation

Create an explicit runtime manifest for each local provider, containing immutable source/model revisions, Python version, platform/architecture, dependency lock hashes, required files and checksums, license identifiers, worker protocol version, and qualified hardware profiles. Keep model download/update separate from app source synchronization.

Build ACE-Step in its own arm64 environment. Do not run its interactive launch scripts at app startup: those scripts may install/update dependencies and are not a reproducible application runtime. The user should be able to install/repair the feature inside Nativ. A release may bundle the runtime or install a versioned prebuilt runtime archive on demand, but the latter needs an authenticated, integrity-checked manifest/archive and a tested download/extract/rollback path. No curl-pipe-shell, mutable main branch checkout, or runtime pip upgrade.

Preserve the base server runtime and its image/chat/STT/TTS behavior. Include all native libraries and codec requirements, ensure relative load paths work from a signed app, and verify packaging without relying on a developer's Homebrew PATH. If an export codec is missing, show an actionable unsupported format; never save a WAV with an .mp3 extension. Account for FFmpeg and library licensing when shipping binaries.

Mac signing/notarization tests must cover nested interpreters, workers, dylibs and runtime archives. Do not disable release security settings just to make an unsigned helper load. Use Nativ's current release conventions and report any owner certificates/keys still required. Downloads must check available disk space for both compressed and expanded runtime/model files, support cancellation/resume, and never delete an unrelated model directory.

### 8.2 Compute admission applies to API requests too

Use one shared compute-admission boundary for local heavyweight music and Nativ's other local inference. Do not claim that InferenceActivityCoordinator alone supplies this boundary. Reuse a compatible coordinator from the translation feature if present; otherwise add a small shared lease mechanism with host/server/worker adapters.

Required policy:
- Active local Chat, Images, STT/TTS or Live Translate prevents starting a new exclusive local music job.
- Queued music does not load weights while waiting. Existing in-flight work is not killed to make room.
- While local music owns its exclusive lease, a conflicting new inference request receives a clear busy response or joins an explicitly supported queue; it never runs concurrently through an unguarded API path.
- A live translation session has priority over starting queued music. If translation is requested while a non-pausable music job runs, offer explicit cancel-and-start or wait; never simulate pause or silently restart a song.
- Hosted/remote generation does not claim the Mac's inference lease, although local playback still participates in audio coordination.
- All terminal paths, exceptions, cancellation, process death and shutdown release the lease only after the actual owned inference and child processes have stopped.

A cross-process advisory shared/exclusive lock with process-owned descriptors is one suitable implementation when no coordinator exists: ordinary active inference holds a shared lease, music generation holds an exclusive lease. Lock ownership must cover the actual inference/stream lifetime, not merely HTTP submission. Combine cross-process locks with correct in-process request coordination; one shared global descriptor is not proof that two requests exclude each other. If using this approach, test process-exit release, two concurrent requests in the same process, two processes, and music waiting while a streamed chat response is still active. Avoid adding a broad new scheduling framework when a narrow adapter suffices.

Server death must not leave an orphan worker generating after its lease disappeared. Keep admission ownership effective for the worker's entire lifetime: use a tested parent-death watchdog/owned process strategy that terminates children, or retain blocking admission until restart recovery proves the old worker has exited. Do not release a lease just because Cancel was requested. Test SIGKILL of the server with a live worker, immediate restart and a competing inference request. Check worker identity rather than killing a reused PID or every Python process.

Admission is also memory-aware. A supposedly idle but resident large model can still prevent music from fitting. Use the existing supported unload/cache mechanism under the appropriate lease and do not discard another feature's active context. Display Waiting for memory or offer a smaller profile; never silently move the request to a paid provider. Check available unified memory, memory pressure and thermal signals, and leave enough for macOS/UI. Do not equate checkpoint download size with peak runtime memory.

Pause music playback when an active microphone/translation workflow would otherwise capture it, using the shared audio coordinator. Resume only according to the user's explicit playback preference. Stop playback cleanly on output-device changes or route loss; a voice feature should not leave a song playing unexpectedly through speakers.

### 8.3 Keep the shared HTTP event loop responsive

Inspect the selected packaged mlx-vlm image generation and edit handlers. At the research pin they call get_cached_model and _generate_all synchronously inside async handlers, blocking the ASGI loop. Prefer a pinned upstream version with a verified fix. If still present, carry a small version/hash-guarded packaging patch confined to these handlers and a dedicated execution helper; include it in the runtime fingerprint and fail clearly on an unexpected source layout.

Keep request reading, authentication and async admission on the ASGI loop. Submit the full blocking image load/generate-or-edit/encode operation to one dedicated serial MLX execution worker and await it asynchronously. Give that worker explicit MLX stream ownership and coordinate cache unload/replacement under the same lifetime lease. The current mlx-audio InferenceBroker is a useful implementation precedent, not proof that this refactor is automatically safe. Preserve image routes, payloads, responses and authorization.

Do not call asyncio.to_thread on an async handler, forward a live ASGI request across event loops, scatter MLX operations across arbitrary pool threads, or increase Uvicorn worker count as a shortcut. Persist/acknowledge music jobs before waiting for compute; status/events/cancel must never wait for an inference lock. Test both Images generation and edits concurrently with Music info/status/events/cancel and health, using a slow deterministic worker and real Apple Silicon inference. Verify cache lifecycle, serial image execution and shutdown. If the dedicated worker fails qualification, a separate inference process behind the control service is an explicit fallback requiring a bounded design update, not a hidden broad rewrite.

## 12. Acceptance criteria and concrete performance targets

Release acceptance:
- Music exists beside Chat and Images and follows the current native design.
- A real local ACE-Step generation works on the qualified Apple Silicon profile without altering the base MLX runtime.
- MiniMax Music3 through the current mlx-audio MXFP8 route and Stable Audio 3 Small Music through its official MLX route are implemented as real local providers, with qualification status and measured limits.
- MiniMax local/remote/cloud routes are clearly distinguished and never advertised beyond their actual verified availability.
- At least one accessible official hosted alternative has a real implemented adapter; every enabled adapter has current contract tests.
- UI and API operate on the same durable job, session and asset identities.
- Canonical stores have persistent identities and one scheduler; remote-server playback uses an authenticated disposable client cache.
- External clients can discover, submit, observe, cancel, resume, download, manage references, trash and restore safely, with required idempotency and authentication.
- Crash recovery does not automatically resend unresolved remote submissions or dispatch recovery-held work; uncertain cancellation retains its remote capacity reservation until reconciled or deliberately released.
- Python alone mutates canonical music originals/references/trash, and Swift reference reconciliation prevents used songs from being deleted.
- Files, actual audio metadata and generation parameters persist correctly through restart and upgrade.
- Playback is usable and native; generated music is a first-class artifact.
- Existing chat/images/voice, and Live Translate when present, retain their behavior.
- Music control routes remain responsive during actual image generation and editing in the selected bundled runtime; an orphan worker cannot bypass compute admission after server restart.
- Upstream merges and own binary updates are separate and tested.

Engineering targets, not measured claims:
- Submit a ready-model job and return its 202 acknowledgment within one second on an idle local server; do not wait for generation.
- Local status, cancel acknowledgment and health remain below a one-second response target while an image worker is busy; record measured percentiles and distinguish network latency for remote canonical servers.
- Reflect committed job state in the active UI within one second while connected, using bounded events/polling.
- A Cancel click responds visually immediately; queued cancellation prevents execution; an owned unresponsive local worker is stopped within a documented bounded grace period, initially five seconds, plus verified OS termination time.
- Playback/seek/scroll remains responsive while generation runs; no long model/decoder work on MainActor.
- No growth in active workers, event queues, file descriptors or retained waveform buffers across 20 sequential jobs.
- Preserve valid original audio even if preview generation, export conversion, or a cloud account later fails.

There is no universal promised song-generation speed. Record real measurements for each Mac chip/RAM, duration, checkpoint, quantization, LM setting, sampler and cold/warm state. Only offer long durations and optional profiles after they pass their own measured limits. Do not use A100 numbers to market a Mac build.

Verification commands must come from the actual project. Expected starting points include make xcode-generate, make xcode-build, targeted xcodebuild test invocations, and python3 -m unittest discover -s scripts/tests -p 'test_music*.py' -v where that matches the chosen test framework. If introducing pytest for worker tests, lock its test dependency and provide the exact reproducible command. A test file excluded by project.yml or -only-testing does not count as a passing gate.
